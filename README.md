# Mirmir

Mirmir is a single native binary combining a local model runtime, Ratatui
dashboard, CLI, private gRPC transport over a Unix socket, Hugging Face model
management, and an optional OpenAI-compatible HTTP server.

Its persistent contract is:

- configuration: `~/.config/mirmir`;
- state and fallback socket: `~/.local/state/mirmir`;
- runtime socket: `$XDG_RUNTIME_DIR/mirmir/mirmir.sock` when available;
- environment variables: `MIRMIR_*`.

The crate declares a versioned crates.io dependency on `libmir` and is designed
to build independently from its published dependency graph.

Install the released binary from crates.io and verify its version:

```sh
cargo install mirmir
mirmir --version
```

The former `cli`, `config`, `server`, and `web` packages are excluded from the
active workspace. They remain temporarily as frozen migration references; the
root package produces the only active application binary.

```sh
cargo run -- config init
cargo run -- config edit
cargo run -- serve
cargo run -- status
cargo run -- prompt --model /path/to/model --prompt "Hello"
cargo run -- prompt --model qwen --prompt "Hello" --warmup 1 --samples 5 --json
cargo run -- model search "Qwen 2.5" --limit 10
cargo run -- model pull Qwen/Qwen2.5-0.5B-Instruct
cargo run -- model list
cargo run -- model inspect Qwen/Qwen2.5-0.5B-Instruct
cargo run -- model load Qwen/Qwen2.5-0.5B-Instruct
cargo run -- model load Qwen/Qwen2.5-0.5B-Instruct --force
cargo run -- model remove Qwen/Qwen2.5-0.5B-Instruct
```

The initial configuration generated by `config init` can select a default model:

```toml
schema_version = 1
default_model = "qwen3-4b"

[runtime]
kv_block_size = 16
kv_blocks = 4096
kv_cache_dtype = "auto"
max_batch_requests = 16
max_batch_tokens = 8192
# Optional hard cap on the resized image area.
vision_max_pixels = 1048576
# Optional fixed attention workspace cap. Omit for the automatic RAM-based limit.
# vision_attention_budget_bytes = 1073741824
# Automatic mode uses this percentage of memory available after model loading.
vision_memory_percent = 80

[server]
http_bind = "127.0.0.1:8080"
allow_remote = false
web_enabled = false
cors_origins = []
body_limit_bytes = 29360128
request_timeout_seconds = 300
max_concurrency = 16
```

Named models live under `~/.config/mirmir/models`:

```toml
# ~/.config/mirmir/models/qwen3-4b.toml
schema_version = 1
id = "qwen3-4b"
path = "/path/to/qwen3-4b"

[generation]
max_tokens = 256
temperature = 0.7
top_p = 0.9
```

Set an HF token without exposing it in shell history by piping it on stdin:

```sh
printf '%s' "$HF_TOKEN" | cargo run -- config set-hf-token
```

The optional HTTP bearer token is stored in the same protected secrets file:

```sh
printf '%s' "$MIRMIR_HTTP_API_KEY" | cargo run -- config set-http-api-key
```

The current implementation includes the versioned TOML foundation, protected HF
secret storage, a versioned gRPC service over a Unix socket, shared model
list/search/load/unload operations, and the first single-prompt path through
public `libmir` APIs. Hub search uses the configured token when present and
prioritizes results by `libmir` architecture compatibility and a conservative
machine-memory fit estimate.

Running `mirmir` without a subcommand opens the Ratatui dashboard and either
attaches to an existing server or owns a temporary local one. TUI, `prompt`, and
model commands share the same lock-aware connect-or-start path: stale socket
files are replaced, concurrent launches converge on one server, and a client
retries while another process is between acquiring the lock and exposing gRPC.
Only the client that actually started a temporary server shuts it down. Workspace tabs are
shown in a bar above the active view with `[F1]`–`[F6]` shortcut labels. Use
`Tab`/`Shift+Tab`, those function keys, or the mouse to switch tabs. The footer exposes
`? help`; it opens a context-sensitive popup containing the complete key map for
the current tab. `Esc` opens an explicit exit confirmation instead of closing
immediately. Lists support arrows, page navigation, Home/End, the mouse wheel,
and row selection by click. On Models, `Enter` or a row click downloads a remote
Hub result, loads an available local model, or unloads a ready model. Models
registered under `~/.config/mirmir/models` and snapshots found in
the standard Hugging Face cache are visible immediately in one model list. An
empty search shows locally available models; a non-empty search replaces that
list with Hub results. Use `Up` and `Down` to select a model. Press `/` to enter
a Hub query and `Enter` to search.
Hub results already present locally are marked `MIRMIR` or `HF CACHE` according
to who owns the snapshot.
Press `d` to download a supported result. Pressing `r` always opens a destructive
confirmation popup before removing either a Mirmir-managed or external HF-cache
entry. Supported models that fit, are tight, or have an unknown estimate are
shown first; incompatible and over-budget remote results are hidden by default
and toggled with `i`. Gated results are marked explicitly, while locally cached
matches always remain visible. Snapshot progress is streamed through gRPC. Downloads use a dedicated
`hf-hub` cache under `~/.local/state/mirmir/hf-hub`, while their declarative model
records remain under `~/.config/mirmir/models`. During a transfer, Models shows
a bordered progress bar with its phase, repository, percentage to 0.1%, and
downloaded/total binary size. A phase without a known total uses an animated
indeterminate state instead of presenting a false percentage.

On a downloaded result, `l` loads the model into the shared runtime and `u`
unloads it. The same identifier can be used from CLI, for example
`mirmir model load Qwen/Qwen2.5-0.5B-Instruct`. Loading streams the weight-transfer
events exposed by `libmir`. Before loading, the TUI opens a settings dialog with
the model defaults or saved Mirmir overrides for max tokens, temperature, top-p,
top-k, and repetition penalty. The dialog also shows an exact local estimate for
weight files, the configured KV cache, runtime workspace, the current safe device
budget, and the maximum safe context. A load that exceeds that budget is rejected
by the server for TUI, CLI, gRPC, and HTTP auto-load alike. Press `f` in the dialog
or use `mirmir model load MODEL --force` to make an explicit override. Confirmed
values are persisted in the model TOML;
the settings form is replaced by a stage-only loading popup. It remains visible
until the model is ready, distinguishes weight mapping from indeterminate backend
initialization, and closes automatically on success. Weight progress advances
only after each safetensors shard has actually been materialized. `mirmir model
list` reports the persistent states
`available`, `loading`, `ready`, or `missing`, together with the pinned Hub
revision and commit.

After a successful load, both the recent history and the persistent active-model
set are stored in `~/.config/mirmir/state.toml`. Unloading a model removes it from
the active set. A later `mirmir` run restores those models sequentially with their
saved per-model generation settings and displays `RESTORING MODELS n/N` together
with the normal stage and shard progress. `mirmir serve` starts its HTTP listener
first and restores the same set in the background, allowing the web dashboard to
show the exact startup target, stage, and progress before the runtime is ready.
Because this file is managed state rather than user configuration, malformed or unsupported contents are quarantined as
`state.corrupt-<timestamp>-<pid>.toml` and replaced with an empty valid state. The
recovery is logged and published in Activity; malformed `config.toml` remains a
startup error. A downloaded snapshot is inspected through
the public `libmir::ModelDescriptor` contract before its model configuration is
registered.

Chat streams a multi-turn conversation through the same
local gRPC server, renders token events at interactive frame cadence, and displays
time to first token together with separately measured prefill and decode
throughput. While the model is working, an animated `Thinking...` placeholder is
shown and the prompt input remains locked until the first request completes.
Otherwise the input is always active. Reasoning enclosed by `<think>` markers is
rendered with a dimmed style. Scroll the conversation with the mouse wheel,
`Up`/`Down`, `PageUp`/`PageDown`, `Home`, or `End`; use `Ctrl+Left` and
`Ctrl+Right` to switch loaded models and `Ctrl+K` to clear the conversation.
Dropping one PNG, JPEG, WebP, or GIF file into Chat attaches it to the prompt;
some terminals paste the path first, in which case `Enter` confirms the
attachment. `Ctrl+D` removes it. Images are limited to 20 MiB.
`Ctrl+P` opens parameters for the selected model: max tokens, temperature,
top-p, top-k, repetition penalty, and an optional one-off seed. Press `s` before
applying to persist all parameters except the seed as that model's Mirmir defaults;
otherwise they remain one-off Chat overrides.
During generation, `X` requests cooperative cancellation; the input remains
locked until the server confirms termination.

`mirmir prompt` is the non-interactive benchmark path. It accepts a prompt from
`--prompt`, `--prompt-file`, or `--stdin`, reuses an existing server when one is
available, and otherwise owns a temporary server for the duration of the run.
`--warmup` and `--samples` (also available as `--bench-warmup` and
`--bench-samples`) control repeated measurements. The JSON report contains raw
samples plus distributions for E2E, TTFT, prefill, decode and their durations:
mean, median, p50, p95, population standard deviation, min and max. `--csv PATH`
exports the raw samples in a comparison-friendly table while `--json` writes the
complete report to stdout.
`Ctrl+C` cancels an in-flight generation and still shuts down a server owned
temporarily by the command.

The `[F6] Bench` dashboard tab runs the same server-side benchmark path. Type a
repeatable prompt, select a loaded model with Left/Right, change sample count
with Up/Down and warm-up count with PageUp/PageDown, then press Enter. Results
show the same distributions and retain an in-memory run history for model
comparison. `Ctrl+E` exports the latest run as JSON and CSV under
`~/.local/state/mirmir/benchmarks`; `X` cancels the active sample.

`mirmir serve` exposes gRPC on the private Unix socket and, by default, an
OpenAI-compatible HTTP listener on `127.0.0.1:8080`. `--no-http` keeps only the
socket, while `--http-bind` or `MIRMIR_HTTP_BIND` overrides the configured
address for the current process. Serve mode emits structured tracing logs to
stderr at `INFO` by default, including HTTP requests, generation summaries,
transport startup, active-model restore, weight progress, ready/unload events,
and shutdown. A general `RUST_LOG=warn` is layered on top without hiding this
baseline; use an explicit target to change it, for example
`RUST_LOG=mirmir=trace,libmir=debug mirmir serve` or
`RUST_LOG=mirmir=warn,libmir=warn mirmir serve`. The first HTTP contract includes:

- `GET /health`;
- `GET /v1/models`, listing only models ready in the shared runtime;
- `POST /v1/chat/completions`, with regular JSON and `stream: true` SSE responses.

Reasoning-capable models expose model-independent `reasoning_content` separately
from final `content` in both JSON responses and streamed deltas. Native model
markers and channel headers are normalized by `libmir` rather than leaked into
the HTTP contract.

```sh
curl http://127.0.0.1:8080/v1/models \
  -H "Authorization: Bearer $MIRMIR_HTTP_API_KEY"

curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $MIRMIR_HTTP_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen","messages":[{"role":"user","content":"Hello"}],"stream":true}'

IMAGE_DATA=$(base64 < image.jpg | tr -d '\n')
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $MIRMIR_HTTP_API_KEY" \
  -H 'Content-Type: application/json' \
  -d "{\"model\":\"MODEL_ID\",\"messages\":[{\"role\":\"user\",\"content\":[{\"type\":\"image_url\",\"image_url\":{\"url\":\"data:image/jpeg;base64,$IMAGE_DATA\"}},{\"type\":\"text\",\"text\":\"Describe this image\"}]}]}"
```

Bearer authentication is optional on loopback. A non-loopback bind requires
both `server.allow_remote = true` and an API key from `secrets.toml` or
`MIRMIR_HTTP_API_KEY`. CORS is disabled unless exact origins are listed in
`server.cors_origins`; body size, timeout, and concurrency are bounded by the
remaining server settings.

The web dashboard is opt-in. Setting `server.web_enabled = true` embeds and
serves Overview, Models, Chat, Settings, and Activity at `/ui/`; `/` redirects to the shell.
One authenticated WebSocket at `/api/mirmir/v1/ws` carries startup readiness,
live telemetry, model snapshots, configuration, and lifecycle activity to every
view without periodic HTTP polling. Models lists configured and
discovered local snapshots, can search Hugging Face with the same compatibility
and memory-fit ranking as TUI, and exposes load, unload, and download actions.
Models also exposes removal confirmation and editable generation defaults before
load. Chat streams content and reasoning separately, shows live and final
TTFT/prefill/decode/E2E metrics, supports cancellation, and accepts an image by
drag-and-drop or file picker with a local preview. Settings presents
effective TOML sources and write-only secret management. Activity consumes a
WebSocket projection of the same runtime stream as TUI and displays the real
lifecycle stage and byte/weight progress. Versioned APIs live under
`/api/mirmir/v1`, separate from the OpenAI `/v1` API. The assets use the same
MiRMiR visual identity as the TUI and project site: the approved vector lockup,
topographic motif, design tokens, and self-hosted Space Grotesk, Inter, and
JetBrains Mono fonts. Every asset is compiled into the single binary.

Opening the shell creates an eight-hour local browser session backed by a random
`HttpOnly`, `SameSite=Strict` cookie. Session creation validates an exact local
Origin/Host pair. A CSRF token is kept only in page memory and is required by
every management mutation. Sessions are
bounded in memory, the UI remains restricted to a loopback bind, and responses
carry a strict CSP and browser security headers. OpenAI bearer authentication is
not accepted as web-session or administration authority.

The Overview dashboard receives a server-side telemetry snapshot over the shared
WebSocket every second. For
active requests, protocol v1 reports the current stage and elapsed time, live
prompt/completion token counters, an advancing TTFT wait, and current aggregate
E2E, prefill, and decode throughput. Idle cards fall back to the last completed
request, while means are explicitly calculated only from completed requests.
The dashboard also shows exact aggregate KV block occupancy and accelerator
memory obtained from public `libmir` APIs. The server samples E2E, prefill,
decode, TTFT, memory, KV occupancy, and request counters every second. It keeps
900 samples and atomically persists them in
`~/.local/state/mirmir/telemetry.toml`; every attached dashboard renders the same
latest 60 samples and recovers them after a restart. Metal reports active and cached
unified memory. CUDA reports driver-level free/total device memory plus pool
usage, so Hub fit ranking accounts for allocations owned by other processes.

Settings reads configuration through protocol v1 and shows persisted values,
their TOML/default source, configuration paths, and restart requirements. Values
can be edited in place; optional runtime fields accept `auto`. HF tokens and HTTP
API keys are write-only over gRPC, masked while typing, and returned only as a
configured/source status. On the HF token row, `t` verifies the current effective
token against the Hub and `r` removes the value stored in `secrets.toml`. When a
server is running, `mirmir config show`, `set`, and secret operations use that
server as the sole writer. For example:

```sh
mirmir config set server.request_timeout_seconds 600
mirmir config test-hf-token
```

Activity is a server-owned, protocol-v1 stream shared by every attached client.
It records the latest state and stage of model restores, loads, Hub downloads,
and generations. The TUI keeps the most recent operations visible across tab
changes; select one with `Up`/`Down` and press `X` to cancel it when marked
cancellable. Generation cancellation is checked before prefill, after prefill,
and between decode steps. Dropping an HTTP/gRPC generation stream also triggers
the same cooperative path once the producer observes the disconnected receiver.
Loads and downloads are displayed but deliberately marked non-cancellable until
their backends expose a safe interruption boundary.

Safe cancellation boundaries for model load and Hub download, plus deeper
backend timing than the public `libmir` metrics currently expose, remain future
implementation stages.
