# MiRMiR 0.4.2

Operators can now administer a MiRMiR service running under a separate,
non-login account from their own CLI or terminal dashboard.

## System instance administration

- `mirmir --system` connects to `/run/mirmir/mirmir.sock`.
- `mirmir --socket /path/to/runtime.sock` selects another existing instance.
- Explicitly selected clients never start a replacement runtime or fall back
  to the operator's local configuration when connection fails.
- Status, configuration, model operations, and generation use the selected
  service. An omitted prompt model uses that service's configured default.
- The TUI identifies the connected instance and socket; closing it leaves the
  service running.
- System servers create a group-accessible socket. Custom server sockets can
  enable group access with `serve --shared-socket`.

The service retains its private configuration, model storage, and secrets.
Operators receive administrative access through the socket's OS group.
See the [system instance guide](../system-instance.md) for systemd configuration
and acceptance tests on a Linux staging server.

The lockfile also updates the transitive `chacha20` dependency from the yanked
0.10.1 release to 0.10.2.

## Install

```sh
cargo install mirmir --version 0.4.2 --locked
```

Update both the service and operator binaries, then restart the service with
the socket and group settings from the guide.
